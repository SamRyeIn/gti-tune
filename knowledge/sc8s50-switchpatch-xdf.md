# SC8S50 Switch Patch XDF (v1.005, switchpatch 29.33)

A TunerPro definition file for the [[Simos 18.1]] SC8S50 platform (2017 GTI, `5G0906259L_0002`). Unlike a raw auto-generated dump, this is a **curated, tuning-focused XDF** — its ~900 tables are the ones you actually tune, organized into human-meaningful categories that line up with the [[ecu-tuning-basics]] SOP, plus a set of **patched-in features** (the "switch patch").

| CATEGORY | 75 |

Addressing and scaling conventions match the other SC8S50 XDFs (0x200000 base offset; linear `MATH` equations), so it loads against the same 4 MB `bin/5G0906259L__0002.bin`. See [[xdf-bin-library-requirements]] for how the library consumes these.

## What "switch patch" means

The defining feature: **on-the-fly map switching**. The BIN is patched so multiple tune calibrations coexist and can be selected while driving (commonly via the cruise-control stalk). The XDF exposes this through:

- **Map Switching** (`0x32`) and a second **Map Switching** group (`0xFB`) — the switching logic/config.
- **Map Slot 1–5** (`0xF3`–`0xF7`) — five selectable calibration slots.
- **Switch Patch** (`0xFF`) — the patch's own control tables.

The `29.33` in the filename refers to the switch-patch version this XDF is built to match. **A switch-patched BIN is not stock** — per [[ecu-tuning-basics]], any bin patch (MPI/SWG/HSL/switch) requires a **full flash**, not a CAL-only flash.

## Category structure

The 75 categories fall into two bands.

### Core tuning categories (low indices `0x0`–`0x34`)
Map directly onto the tuning SOP:

- **Airflow model** — Airflow; Torque to Airflow / Airflow to Torque, each split **Port Flap High / Low** (`0x25`–`0x28`); Torque Model / Torque Management / Torque Request.
- **Boost** — Boost, Wastegate, PUT Setpoint, Manifold Max Pressure, Turbocharger / Compressor / Turbine, Boost Sensors.
- **Timing** — Base / MBT / Minimum, each split **Port Flap High / Low** (`0x1B`–`0x20`); Knock.
- **Fueling** — Fuel, Lambda Control, Mass Fuel Flow, LPFP / Closed Loop LPFP, HPFP, MPI / MPI Inhibitors, Flex Fuel / Ethanol Adjustment.
- **Limits & misc** — Limiter, Speed, RPM, Cooling System, Transmission (AT / MT), Camshaft, Operating Point, Enable Conditions, Inhibit, Immo Power Class.
- **Poops n Craps** (`0xD`) — pops & bangs / impulse combustion (the "DSG sharts" and burble tables from the SOP).
- **Monitoring REQUIRES ECM3 CHECKSUM** (`0xA`) — monitoring tables that only take effect with an ECM3 checksum; a caution flag baked into the category name.

### Patch-added feature categories (high indices `0xAF`, `0xC3`, `0xEC`–`0xFF`)
Features introduced by the patch, beyond stock calibration:

- **Launch Control** (`0xC3`) and **LC** (`0xF9`)
- **TC** — traction control (`0xF8`)
- **NLS** — no-lift shift (`0xFA`)
- **RAL** (`0xFD`)
- Logging/display helpers — **IAT / TQ / Lambda / PUT / Spark / Knock / Flex Fuel** groups (`0xEC`–`0xFE`), e.g. *"Enable PID 0x52 (set to 196 for logging to display manual e content)"*.
- **Map Switching / Map Slots / Switch Patch** (`0xF3`–`0xFF`) as above.

## Practical notes

- This is the XDF to use when tuning a **switch-patched** BIN with selectable maps; the curated category layout makes it the more ergonomic day-to-day definition.
- Because it's switch-patched, edits land across the map slots — understand which slot a table belongs to before editing.
- For the Python library, **this curated XDF does not currently load** (see below); the BinToolz definition is the one to use against a switch-patched bin.

## Which XDF loads under `simoscal` (BTP-adapter U1, 2026-07-10)

Resolved offline while building the BTP patching adapter (see
[[bintoolz-btp-patching]] "U1 findings"): the authoritative XDF for a
switch-patched bin, and the one that **loads under `simoscal`**, is BinToolz's own
**`BinToolz-main/definitions/S50 Switch Patch.29.33.V2.xdf`** — 185 tables, all 123
Map Slot 1–5 / Map Switching tables resolve and decode without codec error.

The curated `v1.005`/`v1.006` here **fail to load**: they map all five slots of a
table onto a **single reused `uniqueid`** at different addresses
(`uniqueid 0x11f9c reused with DIFFERENT data`), which `simoscal`'s
uniqueid→single-location model rejects. BinToolz's XDF gives each slot a distinct
`uniqueid` (e.g. RPM-limiter slots `0x7cb40`/`0x7cb42`/…), so it maps cleanly.

Loading these 1.80 XDFs also required a small parser fix in `simoscal/xdf.py`: a
non-z `XDFAXIS` whose `<EMBEDDEDDATA>` has no `mmedaddress` is a TunerPro
**label/static axis** (breakpoints from `<LABEL>`s, flagged
`mmedmajorstridebits="-32"`); the parser now treats it as a label axis rather than
raising. The default `SC8S50.V1.0.xdf` has none of these, so that fix is
behavior-preserving there.
